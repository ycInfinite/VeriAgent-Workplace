# 第三课：避免用一个正确数字讲出错误结论

实验结论必须说明“测了谁、测了什么、分母是什么”。今天 reference replay 24/24 reward=1，是脚本与 verifier 的结果，不是 Qwen3-8B 的 100% success。还没有模型权重参与运行。

## 四种数据角色

Training 用于参数更新和训练数据生成；development 用于调试与失败分析；checkpoint validation 用于选权重；final evaluation 用于冻结方案后的最终检验。

同一任务的成功和失败轨迹仍属于同一个 pool。不能把成功放训练、失败放测试。换个说法、换个 ID 也不自动变成独立任务。

当前保守清单中，训练候选 743、dev 85、checkpoint validation 93、未合格的组合预留 181。另保留官方验证过滤子集 540。原始数据仍在，没有删除不利结果或改写任务。

## 为什么相似不一定是泄漏

“删除 Alice 的客户”和“删除 Bob 的客户”可能高度相似，但语义目标不同。相似度只能提出风险候选，不是自动裁决。我们发现 148 条 train 任务有跨官方 split 高词面相似候选，保守扩大到模板组后隔离 153 条。这会损失一些可用数据，但避免靠主观挑选保留。

另一方面，没有完全相同的字符串也不能证明没有泄漏。我们把结论写为“已发现的候选边已排除”，不写“语义泄漏为零”。

## 工具出现过，到底是哪一种出现

1. schema 里出现：模型知道有这个函数的定义。
2. trajectory 里调用过：模型见过它在环境中的使用。
3. supervised target 中出现：模型参数因相应决策接受了训练信号。

这三者不能互换。本数据每条 prompt 都有 27 个 schema，但 reference 常常只有最终写操作，前置查询不在其中。我们已经执行过检索→回复两工具路径，却还不能证明存在足够的“所有单工具在 training 执行过，而特定依赖组合只在 final 出现”的独立任务族。

组合应反映依赖，例如“先拿到 ID 再写入”；两个无关查询交换顺序，不一定形成更强的 planning 测试。

## S1 vs S2 如何成为一个实验

问题：固定训练预算下，针对主要失败选择成功/recovery 数据，是否比随机选成功轨迹更有效？

自变量是数据选择规则。模型、训练 token、LoRA 配置、训练步数、评测集、seed protocol 尽量一致。需要同时报告所有处理 token 和真正监督的 token，也要计入 failure-targeted 选择多花的数据生成费用。

S2 如果用了更强 teacher、更多数据、更多训练步数，同时改 prompt，最终更好也无法说明是“failure targeting”带来的。

失败原因需要来自 Base trajectories。当前只有候选 taxonomy，不能先宣称 identifier hallucination 就是 Qwen 的主要失败。

## 成功率与无效 run

以 20 个需要动作的任务为例，四个成功能说明存在成功，但样本仍很小。我们还要看成功是否真实多步、是否 grounded，以及失败是否可重复。

基础设施请求失败应单独标记，不计为模型错；但不能把模型自己循环到 round cap 的失败也排除。费用账单包括两者。零成功时 cost per success 不是零，而是不可定义。

no-op 任务单独分层：如果模型只是总说 Done，也可能拿到部分 reward。资格门槛因此要求在需要实际动作的任务上同时出现成功和失败。

## 你应能复述
